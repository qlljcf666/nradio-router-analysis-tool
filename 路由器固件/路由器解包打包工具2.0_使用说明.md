# 路由器固件 解包/打包工具 使用说明

版本：bate 2.0
适用平台：Windows（64 位）

---

## 一、工具简介

本工具用于对路由器固件镜像进行**识别、解包、编辑修改、重新打包**，并支持对**设备树（DTB）**的扫描、提取、反编译、编辑回写，全程图形界面操作，无需命令行。

- 自动识别固件格式与分区布局（内核 / rootfs / 签名区等）
- 将 rootfs（squashfs 文件系统）解包为普通目录，可直接增删改文件
- 编辑后一键重新打包成可刷写的固件镜像
- **【2.0 新增】** 扫描固件内嵌/独立的设备树 DTB，提取 `.dtb`、反编译为可编辑的 `.dts` 文本，改完再编译写回固件
- 纯本地运行，不上传任何固件数据

## 三、支持的固件格式

工具可自动识别以下 5 类常见路由器固件：

| 类型 | 界面显示 | 典型形态 |
|---|---|---|
| SF_BOOT 私有全 flash 镜像 | `SF_BOOT 私有全 flash 镜像 (SPI NAND)` | 以 `SF_BOOT` 开头，含 uboot + FIT 内核 + squashfs |
| GPT eMMC 裸镜像 | `GPT 分区 eMMC 裸镜像` | GPT 分区表，独立 kernel / root 分区 |
| 裸 UBI 镜像 | `裸 UBI 镜像 (PEB …K)` | NAND 设备的 UBI 卷布局，部分带私有头 |
| legacy uImage 固件 | `legacy uImage + squashfs sysupgrade` | uImage 内核后紧跟 squashfs，尾部可带 JSON/签名 |
| OpenWrt sysupgrade tar | `OpenWrt sysupgrade tar (kernel+root+FWx0)` | tar 包，内含 kernel、root、CONTROL 成员 |

无法识别时会弹窗提示「无法识别的镜像格式」，说明该固件暂不支持。

> 说明：
> - rootfs 重打包仅支持 **xz 压缩**的 squashfs（当前主流固件均为 xz）。非 xz 固件可以解包查看，但日志会警告无法保证打包兼容。
> - **设备树功能**要求内核为 **FIT uImage**（DTB 内嵌在 FIT 的 fdt 节点中）或引导区带**独立裸 DTB**；legacy uImage 若设备树与内核直接拼接，则可能扫不到 DTB。

## 四、界面说明

主界面自上而下：

```
┌────────────────────────────────────────────────────┐
│ 固件文件: [_______________] [浏览…] [识别格式]        │
├────────────────────────────────────────────────────┤
│ 绿色行：识别出的格式名称 / 文件大小                    │
├────────────────────────────────────────────────────┤
│ 分区/成员 ｜ 偏移 ｜ 大小 ｜ 说明（分区结构表）          │
├────────────────────────────────────────────────────┤
│ [解包到目录…] [打包工程目录…] [设备树 DTB…]  (进度) [停止]│
├────────────────────────────────────────────────────┤
│ 日志输出区（显示操作过程与警告）                       │
└────────────────────────────────────────────────────┘
```

- **分区结构表**：列出镜像中各分区/成员的偏移、大小、内容说明（内核、squashfs、签名区等）。
- **设备树 DTB…**：打开设备树操作窗口（见第七章），**2.0 新增**。
- **日志区**：所有操作进度、警告、错误原因都在这里输出，遇到问题请先查看日志。
- **停止**：解包/打包过程中可随时中断。

## 五、固件解包/打包标准流程

### 第 1 步：选择并识别固件

1. 点击 **「浏览…」** 选择固件文件（`.bin` / `.img` / 无后缀均可）。
   选择后会自动识别；也可手动点 **「识别格式」**。
2. 识别成功后，绿色行显示格式名称，下方表格列出分区布局。
   请先确认能正确识别出内核与 rootfs，再进行后续操作。

### 第 2 步：解包

1. 点击 **「解包到目录…」**，选择一个**父目录**。
2. 工具会在该目录下自动创建 `<固件名>_unpack` 工程目录（例如 `C8-600_2.3.3_unpack`）。
3. 等待日志提示「解包完成」。

### 第 3 步：编辑修改

打开工程目录，重点修改 `rootfs` 文件夹内的内容，例如：

- 替换/添加配置文件、脚本、网页文件
- 增删 `etc/`、`usr/` 等目录下的文件
- 修改默认配置、去除不需要的组件等

`kernel` 是内核文件（二进制），**非必要不要改动**。

> 工程目录里以下划线 `_` 开头的文件（如 `_project.json`、`_base.bin`、`_tail.bin`）是打包必需的元数据，**请勿删除、改名或移动**。

### 第 4 步：重新打包

1. 回到工具，点击 **「打包工程目录…」**。
2. 选择第 2 步生成的工程目录（须包含 `_project.json`，否则会提示不是有效工程）。
3. 选择新固件的保存位置与文件名（默认 `<固件名>_new.bin`）。
4. 等待日志提示「打包完成」，即得到可刷写的新固件。

### 第 5 步：刷机

按设备原有的刷机方式（Web 升级 / U-Boot / TFTP 等）刷入新固件。**刷机有风险，请确保已能通过不死 U-Boot 等方式救砖后再操作。**

## 六、工程目录结构说明

| 名称 | 说明 |
|---|---|
| `rootfs/` | **主要编辑对象**，rootfs 文件系统的完整目录树 |
| `kernel` | 解出的内核（FIT / uImage），原样保留 |
| `_project.json` | 工程元数据（格式、偏移、分区参数），打包必需 |
| `_manifest.jsonl` | 文件清单（记录原文件属性，保证可还原重打包） |
| `_base.bin` | 原始镜像副本（SF_BOOT / GPT / UBI 格式，用于就地回填） |
| `_tail.bin` | 原始尾部 JSON/签名块（uImage / tar 格式） |
| `_control.bin` | tar 格式的 CONTROL 成员 |
| `_store/` | 被杀毒软件隔离文件的自动转存区（如出现） |

## 七、设备树 DTB 功能使用说明（2.0 新增）

设备树（DTB，Device Tree Blob）描述开发板的硬件信息（CPU、内存、闪存分区、外设、GPIO 等）。
本工具内置**纯 Python 的 DTB 解析器和 DTS 编译器，无需安装 dtc**，可完成「提取 → 反编译 → 编辑 → 编译 → 回写」全流程。

### 7.1 打开设备树窗口

1. 在主界面 **「浏览…」** 选择固件文件（无需先点识别，选好文件即可）。
2. 点击 **「设备树 DTB…」**，弹出设备树窗口并自动开始扫描。

### 7.2 扫描结果列表

窗口上方表格列出找到的每一个 DTB：

| 列 | 含义 |
|---|---|
| **DTB** | 名称，如 `fdt-1 (FIT 内嵌设备树)` 或 `独立裸 DTB @ 0x370a0` |
| **位置** | 所在容器 / 镜像偏移 |
| **大小** | DTB 字节数 |
| **compatible** | 根节点 compatible（可据此辨认板子型号） |
| **校验** | `签名` / `hash` / `-`，表示该 DTB 所在 FIT 是否带签名或哈希校验 |

- 一个固件可能有**多个** DTB（例如引导区一个独立 DTB + 内核 FIT 里一个内嵌 DTB）。
- 若列表为空，日志提示未发现 DTB —— 该固件可能是 legacy uImage、设备树与内核拼接，或本身无独立设备树。
- 点 **「重新扫描」** 可刷新列表（替换固件后也会自动重新扫描）。

### 7.3 典型修改流程

**① 提取（可选，用于备份/分析）**
- 在列表选中一个 DTB，点 **「提取 .dtb…」**，保存为 `fdt_0.dtb` 等原始二进制文件。

**② 反编译**
- 选中目标 DTB，点 **「反编译为 .dts…」**，选择保存位置（默认 `fdt_序号.dts`）。
- 完成后弹窗询问是否立即用系统默认编辑器打开，点「是」即可编辑。
- DTS 为 dtc 风格文本：字符串属性带引号、数值为 `<…>`、二进制为 `[ … ]`，带 phandle 的节点自动加标签。

**③ 编辑 DTS**
- 用文本编辑器按需求修改，例如调整 LED/GPIO、串口、分区、禁用某外设节点（`status = "disabled";`）等。
- **只改你理解的属性**，保持节点结构、引号、尖括号、分号完整，语法错误会导致编译失败。

**④ 编译并替换**
- 保存 DTS 后回到工具，点 **「编译 .dts 并替换…」**。
- 依次选择：编辑好的 `.dts` 文件 → 新固件保存位置（默认 `<原名>_dtb.bin`）。
- 若该 DTB 带签名/hash，会弹出**校验失效警告**，确认后才继续（见第八章第 2 条）。
- 工具自动完成：DTS 编译为 DTB → 写回 FIT/镜像 → 生成新固件，随后自动重新扫描确认替换生效。

> 整个流程**不修改原始固件文件**，结果另存为新文件，请确认无误后再刷机。

### 7.4 DTB 尺寸限制（重要）

为保证刷写安全，工具采用**不破坏原有分区布局**的就地替换策略：

- **FIT 内嵌 DTB**：新 DTB **不能大于原 DTB**。工具对 FIT 树整体重建，超过原大小时会明确报错。
  因此删除/精简节点一般可行，增加大量内容可能受限。
- **独立裸 DTB**：允许在其后方到下一个镜像对象之间的**空隙内就地扩容**；超过空隙同样报错。

如遇到尺寸超限，请精简修改内容（删除无用节点/属性通常即可缩短 DTB）。

## 八、重要注意事项

1. **不能随意增大镜像。** 工具采用「就地回填、不改变分区布局」策略：
   - 新增/修改的 rootfs 不能超过原 rootfs 分区容量；
   - UBI 格式不能超过原卷的 PEB 数量；
   - FIT 内 DTB 不能大于原 DTB（裸 DTB 不能超过后方空隙）；
   - 超限时操作会明确报错并中止，请精简修改内容后重试。

2. **签名 / 校验会失效。** 若原镜像含 FWx0 签名块，或 FIT 内含 signature/hash 节点，
   修改 rootfs 或替换 DTB 后原有校验值无法重新生成，日志/弹窗会明确警告。
   此类固件只能在**已关闭签名/FIT 校验**（或已破解校验）的设备上刷写，否则无法启动。

3. **杀毒软件可能隔离文件。** 解包过程中部分可执行文件可能被杀软实时防护删除/隔离。
   工具会自动把受影响文件转存到 `_store/` 并在日志告警，以保证仍可重新打包；
   建议操作期间将工程目录加入杀软白名单。

4. **打包仅保证 xz squashfs。** 其他压缩算法只建议解包查看，不建议重打包刷机。

5. **保留原始文件属性。** 对需要执行权限的脚本（如 `init.d/` 下文件），
   工具通过清单还原其权限位；请不要随意删除 `_manifest.jsonl`。

6. **修改 DTS 需谨慎。** 设备树直接对应硬件，错误的 GPIO/分区/内存配置可能导致设备启动失败甚至异常。
   建议修改前先用「提取 .dtb」保留原始备份。

7. **刷机风险自负。** 请确认设备具备救砖手段（不死引导 / 编程器），变砖风险由操作者承担。

## 九、常见问题

**Q：双击 exe 后窗口迟迟不出现？**
A：单文件版首次启动需自解压，等待数秒即可；如长时间无反应，请检查是否被杀毒软件拦截。

**Q：日志提示「未找到 squashfs 超级块，该镜像暂不支持」？**
A：该固件的文件系统不是标准 squashfs，或外层还有未知封装，当前版本无法处理。

**Q：设备树列表为空，提示未发现 DTB？**
A：该固件可能是 legacy uImage（设备树与内核拼接或无独立设备树），当前版本的设备树功能仅支持 FIT 内嵌 DTB 和引导区独立裸 DTB。

**Q：反编译出的 DTS 编译时报错？**
A：通常是编辑时破坏了语法。请检查：字符串引号是否成对、`<…>` 数值括号是否完整、每条属性结尾的分号、节点大括号是否配对。请在原始 DTS 基础上做小步修改。

**Q：替换 DTB 时提示「新 DTB 超过可用空间」？**
A：新设备树比原 DTB 大，超出就地替换允许的范围。请删除不需要的节点/属性精简体积后重试。

**Q：替换 DTB 后刷机能刷入但无法启动？**
A：常见原因：设备开启了 FIT 签名/hash 校验（需先关闭）、DTS 改错了硬件配置。请先用提取的原始 DTB 回退对比，并在能救砖的设备上验证。

**Q：打包 rootfs 时报「过大 / 需要 N 个 PEB，原卷仅 M 个」？**
A：修改后内容超出原分区容量。请删除新增的大文件或精简 rootfs，使成品不大于原镜像分区。

**Q：识别出的固件没有内核或 rootfs 信息？**
A：说明布局与已知模板不符，该固件暂不支持，请勿强行解包打包。
