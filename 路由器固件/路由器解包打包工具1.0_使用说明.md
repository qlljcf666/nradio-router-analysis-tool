# 路由器固件 解包/打包工具 使用说明

版本：bate 1.0
适用平台：Windows（64 位）

---

## 一、工具简介

本工具用于对路由器固件镜像进行**识别、解包、编辑修改、重新打包**，全程图形界面操作，无需命令行。

- 自动识别固件格式与分区布局（内核 / rootfs / 签名区等）
- 将 rootfs（squashfs 文件系统）解包为普通目录，可直接增删改文件
- 编辑后一键重新打包成可刷写的固件镜像
- 纯本地运行，不上传任何固件数据

## 三、支持的固件格式

工具可自动识别以下 5 类常见路由器固件：

| 类型 | 界面显示 | 典型形态 |
|---|---|---|
| SF_BOOT 私有全 flash 镜像 | `SF_BOOT 私有全 flash 镜像 (SPI NAND)` | 以 `SF_BOOT` 开头，含 uboot + FIT 内核 + squashfs |
| GPT eMMC 裸镜像 | `GPT 分区 eMMC 裸镜像` | GPT 分区表，独立 kernel / root 分区 |
| 裸 UBI 镜像 | `裸 UBI 镜像 (PEB …K)` | NAND 设备的 UBI 卷布局，部分带私有头 |
| legacy uImage 固件 | `legacy uImage + squashfs sysupgrade` | uImage 内核后紧跟 squashfs，尾部可带 JSON/签名 |
| OpenWrt sysupgrade tar | `OpenWrt sysupgrade tar (kernel+root+FWx0)` | tar 包，内含 kernel、root、CONTROL 成员 |

无法识别时会弹窗提示「无法识别的镜像格式」，说明该固件暂不支持。

> 说明：rootfs 重打包仅支持 **xz 压缩**的 squashfs（当前主流固件均为 xz）。非 xz 固件可以解包查看，但日志会警告无法保证打包兼容。

## 四、界面说明

```
┌─────────────────────────────────────────────┐
│ 固件文件: [_______________] [浏览…] [识别格式] │
├─────────────────────────────────────────────┤
│ 绿色行：识别出的格式名称 / 文件大小             │
├─────────────────────────────────────────────┤
│ 分区/成员 ｜ 偏移 ｜ 大小 ｜ 说明（分区结构表） │
├─────────────────────────────────────────────┤
│ [解包到目录…] [打包工程目录…]    (进度条) [停止]│
├─────────────────────────────────────────────┤
│ 日志输出区（显示操作过程与警告）               │
└─────────────────────────────────────────────┘
```

- **分区结构表**：列出镜像中各分区/成员的偏移、大小、内容说明（内核、squashfs、签名区等）。
- **日志区**：所有操作进度、警告、错误原因都在这里输出，遇到问题请先查看日志。
- **停止**：解包/打包过程中可随时中断。

## 五、标准操作流程

### 第 1 步：选择并识别固件

1. 点击 **「浏览…」** 选择固件文件（`.bin` / `.img` / 无后缀均可）。
   选择后会自动识别；也可手动点 **「识别格式」**。
2. 识别成功后，绿色行显示格式名称，下方表格列出分区布局。
   请先确认能正确识别出内核与 rootfs，再进行后续操作。

### 第 2 步：解包

1. 点击 **「解包到目录…」**，选择一个**父目录**。
2. 工具会在该目录下自动创建 `<固件名>_unpack` 工程目录（例如 `C8-600_2.3.3_unpack`）。
3. 等待日志提示「解包完成」。

### 第 3 步：编辑修改

打开工程目录，重点修改 `rootfs` 文件夹内的内容，例如：

- 替换/添加配置文件、脚本、网页文件
- 增删 `etc/`、`usr/` 等目录下的文件
- 修改默认配置、去除不需要的组件等

`kernel` 是内核文件（二进制），**非必要不要改动**。

> 工程目录里以下划线 `_` 开头的文件（如 `_project.json`、`_base.bin`、`_tail.bin`）是打包必需的元数据，**请勿删除、改名或移动**。

### 第 4 步：重新打包

1. 回到工具，点击 **「打包工程目录…」**。
2. 选择第 2 步生成的工程目录（须包含 `_project.json`，否则会提示不是有效工程）。
3. 选择新固件的保存位置与文件名（默认 `<固件名>_new.bin`）。
4. 等待日志提示「打包完成」，即得到可刷写的新固件。

### 第 5 步：刷机

按设备原有的刷机方式（Web 升级 / U-Boot / TFTP 等）刷入新固件。**刷机有风险，请确保已能通过不死 U-Boot 等方式救砖后再操作。**

## 六、工程目录结构说明

| 名称 | 说明 |
|---|---|
| `rootfs/` | **主要编辑对象**，rootfs 文件系统的完整目录树 |
| `kernel` | 解出的内核（FIT / uImage），原样保留 |
| `_project.json` | 工程元数据（格式、偏移、分区参数），打包必需 |
| `_manifest.jsonl` | 文件清单（记录原文件属性，保证可还原重打包） |
| `_base.bin` | 原始镜像副本（SF_BOOT / GPT / UBI 格式，用于就地回填） |
| `_tail.bin` | 原始尾部 JSON/签名块（uImage / tar 格式） |
| `_control.bin` | tar 格式的 CONTROL 成员 |
| `_store/` | 被杀毒软件隔离文件的自动转存区（如出现） |

## 七、重要注意事项

1. **不能随意增大镜像。** 工具采用「就地回填、不改变分区布局」策略：
   - 新增/修改的 rootfs 不能超过原 rootfs 分区容量；
   - UBI 格式不能超过原卷的 PEB 数量；
   - 超限时打包会明确报错并中止，请精简修改内容后重试。

2. **签名 / 校验会失效。** 若原镜像含 FWx0 签名块或 FIT 校验，重打包后签名无法重新生成，
   日志会提示「修改内容后签名实际失效」。此类固件只能在**已关闭签名校验**的设备上刷写。

3. **杀毒软件可能隔离文件。** 解包过程中部分可执行文件可能被杀软实时防护删除/隔离。
   工具会自动把受影响文件转存到 `_store/` 并在日志告警，以保证仍可重新打包；
   建议操作期间将工程目录加入杀软白名单。

4. **打包仅保证 xz squashfs。** 其他压缩算法只建议解包查看，不建议重打包刷机。

5. **保留原始文件属性。** 对需要执行权限的脚本（如 `init.d/` 下文件），
   工具通过清单还原其权限位；请不要随意删除 `_manifest.jsonl`。

6. **刷机风险自负。** 请确认设备具备救砖手段（不死引导 / 编程器），变砖风险由操作者承担。

## 八、常见问题

**Q：双击 exe 后窗口迟迟不出现？**
A：单文件版首次启动需自解压，等待数秒即可；如长时间无反应，请检查是否被杀毒软件拦截。

**Q：日志提示「未找到 squashfs 超级块，该镜像暂不支持」？**
A：该固件的文件系统不是标准 squashfs，或外层还有未知封装，当前版本无法处理。

**Q：打包时报「过大 / 需要 N 个 PEB，原卷仅 M 个」？**
A：修改后内容超出原分区容量。请删除新增的大文件或精简 rootfs，使成品不大于原镜像分区。

**Q：打包后刷机能刷入但无法启动？**
A：常见原因：设备开启了签名校验（需先关闭）、误改了 `kernel`、或删除了关键启动文件。
请先在能救砖的设备上验证。

**Q：识别出的固件没有内核或 rootfs 信息？**
A：说明布局与已知模板不符，该固件暂不支持，请勿强行解包打包。
