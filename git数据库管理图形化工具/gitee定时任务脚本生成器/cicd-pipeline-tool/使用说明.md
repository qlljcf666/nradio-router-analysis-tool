# CI/CD 定时编译任务管理工具 使用说明

一个零第三方依赖的 Python tkinter 图形化工具，用于管理 **Gitee Go 流水线** 和 **GitHub Actions** 的定时编译任务：可视化编辑定时、一键启用产物自动发布、git 推送、手动触发、查看运行历史。

## 运行环境

- Windows / Linux / macOS
- Python 3.7+（自带 tkinter 即可，无需安装任何第三方库）

```bash
python pipeline_manager.py
```

## 界面布局

```
┌ 连接设置 ─────────────────────────────────────┐
│ 平台 / 仓库(owner/repo) / 分支 / 令牌 / 代理 / 本地仓库路径 │
├ 选项卡 ───────────────────────────────────────┤
│ ① 定时任务    —— 扫描与启用自动发布              │
│ ② 编辑定时    —— cron 可视化编辑与推送           │
│ ③ 远程任务与运行 —— 触发 / 历史 / 启停           │
│ ④ 日志        —— 操作与错误记录                 │
└───────────────────────────────────────────────┘
```

## 连接设置说明

| 字段 | 说明 |
|---|---|
| 平台 | `gitee` 或 `github`，决定 API 与 cron 表达式格式 |
| 仓库 | 格式 `owner/repo`，如 `qlljcf666/uboot-qsdk12.5-build` |
| 分支 | 推送与触发目标分支，默认 `main` |
| 令牌 | Gitee 私人令牌 / GitHub Personal Access Token（用于 API 调用和 git 推送凭据） |
| 代理 | 可选，如 `http://127.0.0.1:7890`（访问 GitHub 不通时填写） |
| 本地仓库路径 | 本地 git 克隆目录，扫描任务和 git 推送都基于它 |

点「**保存配置**」后写入同目录 `config.json`，下次启动自动恢复。

## 快速上手

### 1. 查看/修改定时

1. 填好连接设置 →「扫描本地任务」
2. 列表显示 `.workflow/*.yml`（Gitee）和 `.github/workflows/*.yml`（GitHub）中含 cron 的文件，"含义"列自动翻译为中文（如"每月 1 号 10:00"）
3. 选中任务 →「编辑选中任务定时」→ 切到「编辑定时」页
4. 选择频率（每天 / 每周几 / 每月几号）和时间，cron 预览框实时生成表达式：
   - Gitee：6 位 quartz（秒 分 时 天 月 星期），如 `0 0 10 1 * ?`
   - GitHub：5 位 POSIX（分 时 天 月 星期），如 `0 10 1 * *`（**UTC 时间**，北京时间 = UTC+8）
5. 「保存并推送到远程」一键完成 修改 → commit → push

### 2. 启用产物自动发布

选中任务 →「**启用产物自动发布并推送**」，工具自动注入：

**Gitee**（`.workflow/*.yml`）：
- `commands` 末尾追加 `RELEASE_TOKEN=${RELEASE_TOKEN} bash ./ci-release.sh`
- 缺少 `artifacts` 段时补上（暂存 `./bin`，流水线产物页可下载，保留 7 天）
- 仓库根目录生成 `ci-release.sh`：编译后自动创建 Gitee Pre-release 并上传 `bin/` 下所有产物

**GitHub**（`.github/workflows/*.yml`）：
- 末尾追加 `softprops/action-gh-release@v2` 步骤，上传 `bin/**`（使用自动授予的 GITHUB_TOKEN，**无需配置令牌**）

已启用或重复执行不会产生重复配置（幂等）。

### 3. Gitee 令牌变量配置（发布后必须）

Gitee 发布需要私人令牌，**不要写进 yml 或脚本**（会进入公开仓库历史）：

1. Gitee 仓库 → 顶部「流水线」→ 点击流水线名 →「编辑流水线」
2. 切到「**变量设置**」选项卡 →「添加变量」
3. 变量名称 `RELEASE_TOKEN`（注意：**不能 `GITEE_` 开头**，该前缀为平台保留）
4. 值粘贴私人令牌 → 确认 → 右上角「**保存**」流水线

原理：Gitee 自建变量是**文本替换**机制，运行时将命令中的 `${RELEASE_TOKEN}` 替换为实际值，日志中自动脱敏为 `******`。

### 4. 远程操作（选项卡③）

- 「加载远程列表」：列出流水线（Gitee）/ workflow（GitHub）
- 「手动触发选中」：立即运行一次（Gitee 走 API，GitHub 走 workflow_dispatch）
- 「查看运行历史」：最近 10 次运行的状态/结果/时间
- 「启用/禁用」：仅 GitHub 支持

## 常见问题

**Q: 点「加载远程列表」报错 HTTP 401/403？**
A: 令牌无效或权限不足。Gitee 令牌需勾选 `projects` 权限；GitHub 令牌需 `repo` + `workflow` 权限。

**Q: GitHub 全部网络错误？**
A: 填写代理后重试；仅定时编辑和 git 推送功能不依赖 API，可正常使用。

**Q: 日志显示「未设置 RELEASE_TOKEN 私密参数，跳过 Release 发布」？**
A: 变量未配置或未保存流水线。按上文"Gitee 令牌变量配置"操作，注意变量名必须是 `RELEASE_TOKEN`。

**Q: 推送失败 non-fast-forward？**
A: 远程有新提交（如在网页端编辑过流水线 yml）。先在本地仓库目录执行 `git pull` 同步，再重试。

**Q: 令牌安全提醒**
A: 令牌只会写入本地 `config.json` 和用于 HTTPS 推送 URL，不会提交到仓库。若令牌曾明文出现在公开仓库/聊天记录，请到平台设置中撤销并重新生成。
