# Git 批量上传下载管理工具 使用说明

## 一、工具简介

本工具是一个图形化的 Git 仓库管理工具，用于在 GitHub、Gitee、GitLab、GitCode 等平台上进行**大量文件的上传与下载**。无需记忆 Git 命令，点击按钮即可完成初始化、克隆、拉取、提交、推送等全部操作。

- **零依赖**：exe 版本内嵌 Python 运行环境，无需安装 Python
- **多平台支持**：自动识别 GitHub / Gitee / GitLab / GitCode
- **安全凭据**：Token 不写入远程 URL，日志自动脱敏
- **批量上传**：一键完成 add → commit → push，适合大量文件
- **实时日志**：所有操作实时输出，便于排查问题

## 四、功能详解

### 4.1 初始化仓库

对选定的本地路径执行 `git init`，创建 `.git` 目录，并自动：
- 切换到指定的默认分支（main/master）
- 若已填写用户名，自动配置 `user.name` 和 `user.email`

### 4.2 克隆仓库

将远程仓库克隆到本地：
- 若本地路径**为空目录**，直接克隆到该目录
- 若本地路径**非空**，则在该目录下创建以仓库名命名的子目录进行克隆

### 4.3 拉取更新

执行 `git pull origin <分支>`，从远程拉取最新代码合并到本地。

### 4.4 查看状态

执行 `git status --short`，显示变更文件列表及数量（最多显示 200 条）。

### 4.5 提交 (commit)

执行 `git add -A` 暂存所有变更，再执行 `git commit -m <提交信息>`。

### 4.6 推送 (push)

执行 `git push -u origin <分支>`，将本地提交推送到远程仓库。

### 4.7 一键上传（核心功能，适合大量文件）

自动完成完整流程，无需分步操作：

1. **初始化仓库**（若目录不是 git 仓库）
2. **配置远程仓库** origin（若已填写 URL）
3. **配置用户身份**（若已填写用户名）
4. **暂存所有文件** `git add -A`
5. **提交** `git commit -m <信息> --allow-empty`
6. **推送** `git push -u origin <分支>`

> 若未填写远程 URL，会弹窗确认是否仅做本地提交。

### 4.8 查看日志

执行 `git log --oneline --graph --decorate -15`，显示最近 15 条提交记录。

### 4.9 设置远程

添加或更新远程仓库 origin 的 URL。

### 4.10 编辑 .gitignore

打开 .gitignore 编辑器，内置常用模板：

| 模板 | 包含内容 |
|------|----------|
| 通用 | .DS_Store、Thumbs.db、*.log、*.tmp、*.zip 等 |
| Python | __pycache__、*.pyc、venv、.idea、.vscode 等 |
| Node.js | node_modules、dist、build、.env 等 |
| Java | *.class、*.jar、target、.idea 等 |
| C/C++ | *.o、*.exe、build、.vs 等 |
| C# | bin、obj、.vs、packages 等 |
| IDE | .idea、.vscode、.vs、*.swp 等 |
| 空 | 空白文件 |

选择模板后点击「应用模板」，可在文本框中继续编辑，最后点击「保存」写入本地路径下的 `.gitignore`。

### 4.11 保存配置

将当前填写的本地路径、远程 URL、用户名、分支、git 路径保存到 `git_manager_config.json`（与程序同目录），下次启动自动加载。

- **Token 默认不保存**。若填写了 Token 并点击保存，会弹出确认框，提示明文保存风险，用户确认后才会写入。

### 4.12 设置 git.exe 路径

若程序未自动检测到 git，可手动选择 `git.exe` 文件。选择后会自动验证版本。

## 五、典型操作流程

### 场景一：上传本地项目到 GitHub（大量文件）

1. 点击「浏览...」选择本地项目文件夹
2. 在「远程仓库 URL」填写 GitHub 仓库地址（如 `https://github.com/用户名/仓库名.git`）
3. 填写「用户名」和「Token」
4. 确认「分支」（一般为 `main`）
5. 填写或修改「提交信息」
6. 点击 **「一键上传 (add+commit+push)」**
7. 等待日志显示 `[成功] 推送完成！`

### 场景二：从 Gitee 克隆仓库到本地

1. 在「远程仓库 URL」填写 Gitee 仓库地址
2. 点击「浏览...」选择本地存放目录（建议选空目录）
3. 填写「用户名」和「Token」（私有仓库必填）
4. 点击 **「克隆仓库」**
5. 等待日志显示 `[成功] 克隆完成`

### 场景三：拉取远程更新

1. 点击「浏览...」选择已克隆的本地仓库目录
2. 确认「分支」正确
3. 点击 **「拉取更新」**

### 场景四：日常提交推送

1. 选择本地仓库目录
2. 修改文件后，可先点「查看状态」确认变更
3. 填写「提交信息」
4. 点击 **「提交 (commit)」**，再点 **「推送 (push)」**
5. 或直接点 **「一键上传」** 一步完成

## 六、Token 获取方式

推送代码需要认证，推荐使用 **个人访问令牌 (Token)** 而非密码。

### GitHub Token

1. 登录 GitHub → 点击右上角头像 → **Settings**
2. 左侧菜单 → **Developer settings** → **Personal access tokens** → **Tokens (classic)**
3. 点击 **Generate new token** → **Generate new token (classic)**
4. 勾选 `repo` 权限（完整仓库访问）
5. 点击 **Generate token**，复制生成的 token（只显示一次）

### Gitee 私人令牌

1. 登录 Gitee → 点击右上角头像 → **设置**
2. 左侧菜单 → **私人令牌**
3. 点击 **生成新令牌**，勾选 `projects` 权限
4. 提交后复制令牌（只显示一次）

### GitLab Token

1. 登录 GitLab → 右上角头像 → **Preferences**
2. 左侧 → **Access Tokens**
3. 填写名称、勾选 `write_repository` 权限
4. 点击 **Create personal access token**，复制令牌

## 七、安全说明

- **Token 不写入远程 URL**：程序通过 HTTP Header 传递认证信息，不会把 token 拼进 URL 存入 git 配置
- **日志脱敏**：远程 URL 和 Token 在日志中自动脱敏，只显示前后 4 位
- **Token 可选保存**：保存配置时会二次确认是否保存 Token，默认不保存
- **凭据记忆**：系统已配置 Git Credential Manager，首次输入 Token 后会自动记住，后续无需重复输入

## 八、注意事项

1. **必须安装 Git**：exe 不包含 Git，运行前需安装 Git for Windows
2. **首次推送认证**：首次推送时 Git Credential Manager 可能弹出窗口，输入用户名和 Token 即可
3. **大量文件上传**：文件数量极多时，`git add -A` 可能耗时较长，请耐心等待日志输出
4. **大文件限制**：GitHub 单文件限制 100MB，Gitee 限制 100MB（企业版 500MB），超大文件建议使用 Git LFS
5. **网络问题**：若 GitHub 连接失败，可尝试使用代理或改用 Gitee 等国内平台
6. **分支名**：新仓库默认分支通常为 `main`，旧仓库可能是 `master`，请根据实际情况选择
7. **配置文件**：`git_manager_config.json` 保存在程序同目录，若保存了 Token请勿将该文件分享或上传

## 九、常见问题 (FAQ)

**Q1：启动后提示「未检测到 git」怎么办？**
A：请先安装 Git for Windows（https://git-scm.com/download/win）。安装后若仍提示，点击界面右下角「设置 git.exe 路径」手动选择 git.exe。

**Q2：推送失败，提示认证错误？**
A：检查用户名和 Token 是否正确。GitHub 已不支持密码认证，必须使用 Token。确保 Token 勾选了 `repo` 权限。

**Q3：推送失败，提示 `fatal: unable to access`？**
A：网络连接问题。检查网络是否能访问目标平台，GitHub 在国内可能不稳定，可尝试使用代理或改用 Gitee。

**Q4：提交时提示 `Please tell me who you are`？**
A：在「用户名」栏填写你的平台用户名，程序会自动配置 git user.name。

**Q5：克隆私有仓库失败？**
A：私有仓库需要认证，确保填写了正确的用户名和 Token。

**Q6：一键上传卡在 `git add -A` 很久？**
A：文件数量多或文件大时暂存耗时较长，属正常现象，等待即可。可先用 .gitignore 排除不需要上传的文件（如 node_modules、.venv 等）。

**Q7：exe 被杀软误报怎么办？**
A：PyInstaller 打包的 exe 偶尔会被部分杀软误报，可将程序加入信任列表，或使用 .py 源码版运行。
