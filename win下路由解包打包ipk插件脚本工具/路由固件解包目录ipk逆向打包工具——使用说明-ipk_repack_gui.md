# 解包目录扫描 → IPK 自动打包工具 使用说明

版本：单文件 exe
适用平台：Windows（64 位）

---

## 一、工具简介

本工具用于把**已解包的路由器 rootfs 里的插件重新打成标准 `.ipk` 安装包**，典型场景是：先用固件解包工具得到 `system_rootfs`，再用本工具按 opkg 登记信息把各个插件（如 luci-app-*）逐个还原成可被 `opkg install` 直接安装的 ipk。

- 自动定位 `usr/lib/opkg/info`，扫描全部 `.control` / `.list`
- 列表显示每个插件的包名、版本、架构、分类、文件数、符号链接数、缺失数
- 支持搜索过滤、仅看缺失、全选/反选、单击勾选、双击查看详情
- 后台线程批量打包，实时进度日志，可随时停止
- 生成的 ipk 为 **OpenWrt 官方格式**（gzip tar：`./debian-binary`、`./data.tar.gz`、`./control.tar.gz`），opkg 可直接安装
- 同时输出**按包归类的文件树**，方便核对、二次修改后手工重打

纯本地运行，单文件 exe 已内置 Python 运行环境，**目标电脑无需安装 Python**。

---

## 二、启动方式

双击 **`ipk_repack_gui.exe`** 即可启动：

- 首次启动需几秒自解压，请耐心等待窗口出现；
- 可拷贝到其他未安装 Python 的 Windows 电脑使用；
- 只有图形界面，没有黑色控制台窗口。

## 四、操作流程

### 第 1 步：选择解包目录

在「**1. 解包目录**」处点「浏览…」选择目录，或直接把路径粘贴进输入框后点「**扫描**」。

可接受的目录（工具会自动向下查找 `usr/lib/opkg/info`，最多找两级）：

1. **rootfs 本身**：如 `...\system_rootfs`（其下直接有 `usr\lib\opkg\info`）；
2. **解包工程目录**：如 `ML-UW-1-5G_xxx_unpack`（一级子目录 `system_rootfs` 里有 info）；
3. 它们的**上级目录**也行，工具会继续向下找一层。

> 小技巧：把 exe 放进解包目录相关位置启动时，程序会尝试自动发现 rootfs；找到就自动填入并开始扫描。找不到时手动浏览即可，不影响使用。
>
> 若所选目录下确实没有 `usr/lib/opkg/info`，会弹出「扫描失败」提示——请确认选择的是解包后的 rootfs 而不是固件原文件。

### 第 2 步：设置输出目录与输出内容

在「**2. 输出设置**」：

- **输出目录**：扫描成功后自动填为解包根目录旁的 `ipk_repack_gui\`，可自行修改。
- **生成 .ipk**：勾选后产出真正可安装的 ipk 包（默认勾选）。
- **生成归类目录 packages/**：勾选后同时把每个包的文件按安装路径复制归类出来（默认勾选）。

两个选项至少要保留一个，否则开始打包时会提示。

### 第 3 步：选择要打包的插件

「**3. 选择要打包的插件**」表格列含义：

| 列 | 含义 |
|---|---|
| 勾选框列 | 单击切换选中（☑/☐），也可选中行后按空格键 |
| 包名 Package | 来自 control 文件的 Package 字段 |
| 版本 / 架构 / 分类 | Version / Architecture / Section |
| 文件 | `.list` 中登记、且 rootfs 里实际存在的普通文件数 |
| 符号链接 | 登记为符号链接的条目数（打包时保留链接目标） |
| 缺失 | 已登记但 rootfs 中不存在的条目数（**红色标记**） |

辅助操作：

- **全选 / 全不选 / 反选**：批量勾选；每次新扫描结果默认**全部选中**。
- **搜索**：按包名或分类实时过滤。
- **仅显示有缺失的包**：快速定位登记不完整的包。
- 右上角统计行显示：总包数、已选包数、存在缺失的包数与缺失总项数。
- **双击任意一行**：弹出该包详情窗口，两个页签：
  - `control / 信息`：完整 control 字段、依赖、描述、conffiles、各类条目统计；
  - `文件清单`：逐条列出 rootfs 内路径与状态（文件/目录/符号链接/缺失，缺失红色、符号链接蓝色）。

### 第 4 步：开始打包

点「**开始打包**」，后台逐个构建所选包：

- 进度条显示 `当前/总数`，下方文字显示正在处理的包名，日志区实时输出过程；
- 再点一次按钮（此时显示「**停止**」）可请求中断，会在**当前这个包做完后**安全退出，已完成的包保留；
- 全部完成后弹出提示框，「打开输出目录」「查看缺失报告」按钮变为可用。

## 五、输出产物

假设输出目录为 `ipk_repack_gui\`，打包后结构：

```
ipk_repack_gui\
├─ ipk\                                  # ★可安装的 ipk 包（勾选"生成.ipk"时）
│   ├─ luci-app-nxdb_1.0.0-1_all.ipk
│   ├─ <包名>_<版本>_<架构>.ipk
│   └─ …
├─ packages\                             # 按包归类的文件树（勾选"归类目录"时）
│   └─ <包名>\
│       ├─ CONTROL\                      # control / conffiles / preinst、postinst…
│       ├─ usr\ …                         # 与设备内安装路径完全一致的文件树
│       └─ xxx.symlink                    # 符号链接标记文件（内容为链接目标）
├─ _manifest.csv                         # 本次打包汇总表（包名/版本/架构/文件数/缺失数/ipk文件名…）
└─ _report.txt                           # 缺失报告：rootfs 路径、打包数量、逐包列出缺失路径
```

### 关于 ipk 格式

- 外层为 **gzip tar**（OpenWrt 官方 ipk 格式），内含三个成员：
  `./debian-binary`（内容 `2.0`）、`./data.tar.gz`（文件数据）、`./control.tar.gz`（control 与维护脚本）；
- tar 内文件均归属于 `root:root`；普通文件权限 0644，可执行文件/脚本 0755，符号链接 0777；
- **没有使用 ar 归档**（路由器 opkg 对 ar 包会报 “Malformed package file”）。

### 自动权限判定

下列文件自动赋予可执行权限 0755，其余为 0644：

- 位于任意 `bin/`、`sbin/` 目录下的文件；
- `.sh`、`.cgi` 后缀文件；
- 文件名含 `.so` 的文件；
- `etc/init.d/`、`etc/hotplug.d/` 下的文件。

### 缺失条目处理

`.list` 中登记、但 rootfs 里实际不存在的文件（常见于未编入 rootfs 的内核模块 `.ko`、`modem_fw` 固件等）标记为「缺失」，**打包时自动跳过**，不会导致失败；打包前建议用「仅显示有缺失的包」和 `_report.txt` 核对，确认这些文件确实不需要。

## 六、典型使用场景

**场景：从鲲鹏无限固件解包结果批量重打 luci/系统插件 ipk**

1. 先用固件解包工具「一键智能解包」，得到 `..._unpack\system_rootfs`；
2. 双击启动本工具，「浏览…」选择 `system_rootfs`（或 `..._unpack` 目录）；
3. 扫描后用搜索框输入 `luci` 过滤，按需勾选要还原的插件；
4. 确认输出目录，点「开始打包」；
5. 完成后到 `ipk_repack_gui\ipk\` 取 ipk，用 `opkg install xxx.ipk` 安装，或自行上传到软件源。

**场景：只想要某个插件的文件结构（不做 ipk）**

- 只勾选「生成归类目录 packages/」，取消「生成 .ipk」，打包后直接从 `packages\<包名>\` 取 CONTROL 与文件树。

## 七、注意事项

1. 工具**只读取**解包目录、向输出目录写入，不会修改 `system_rootfs` 原始文件；但重跑打包时会**清空重建**输出目录下对应的 `packages\<包名>\`，请勿把自己的文件放在该目录里。
2. 重新生成 ipk 不会附带原厂商签名（ipk 本身一般无签名要求，由设备端 opkg 校验链决定）；如设备软件源强制签名校验，需自行处理。
3. 包对其他包的依赖（Depends）原样保留在 control 中，工具不做依赖解析；安装时如缺依赖，opkg 会按其默认行为提示。
4. 维护脚本 `preinst/postinst/prerm/postrm` 与 `conffiles` 若存在会自动收入 `control.tar.gz`，脚本按 0755 权限打包，内容不做改动——打包前可在详情窗口确认。
5. 输出 ipk 文件名中的特殊字符（`\ / : * ? " < > |` 及空格）会自动替换为下划线。
6. 归类目录里的 `*.symlink` 只是方便在 Windows 上查看链接目标的**标记文本文件**，不是实际安装内容；ipk 内记录的是真正的符号链接。

## 八、常见问题

**Q：双击 exe 很久不出窗口？**
A：单文件版首次启动需自解压到临时目录，等待十几秒正常；如被杀毒软件拦截请加白名单。

**Q：扫描提示「未找到 usr/lib/opkg/info」？**
A：选择的目录层级不对。请定位到解包产物中的 `system_rootfs`，或包含它的 `*_unpack` 目录；原始固件 `.bin` 不能直接选，需要先解包。

**Q：某包「缺失」数字很大，能打吗？**
A：可以，缺失项会自动跳过。请先双击该行查看缺失清单（或看 `_report.txt`），确认缺的都是 `.ko`/固件等本就不在该 rootfs 内的文件；若缺的是主程序/脚本，说明解包不完整或文件被杀软隔离，应先补全再打包。

**Q：打出的 ipk 在路由器上安装报权限错误或脚本不执行？**
A：检查该文件是否属于本工具可自动识别的可执行路径（见第五节「自动权限判定」）；不属于规则内、但设备端需要执行权限的文件，可在归类目录中调整后手工重打，或确保其位于 `bin/sbin`、以 `.sh` 结尾等规则路径。

**Q：打包中途想取消？**
A：再点一次「开始打包」按钮（显示为「停止」），工具会在当前包完成后退出，已生成的包和报告保留，可直接继续使用或重新打包。

**Q：日志/详情中文乱码？**
A：本工具读写 control/list 均按 UTF-8 处理，正常不会乱码；若原厂商文件本身是非 UTF-8 编码，control 里个别字符可能被替换显示，但不影响打包结构。
