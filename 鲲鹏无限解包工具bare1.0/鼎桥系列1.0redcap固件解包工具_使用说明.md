# 固件 / NR 备份 可视化解包-打包工具 2.0 使用说明

版本：**2.0**（单文件 exe，绿色免安装）
适用平台：Windows 10 / 11（64 位），无需安装 Python
对应程序：`固件解包工具2.0.exe`

> **2.0 相对 1.0 的主要变化**：页签②「★一键制作解锁备份」新增**第二种注入方式（rc.local 开机一次性脚本）**，与原有的 uci-defaults 方式二选一；NR 解锁、CLI 同步支持 `--method uci|rc`。其余解包/逆向打包功能与 1.0 完全兼容。

---

## 一、工具简介

本工具面向**鲲鹏无限（NRadio / DD-5G 类 moses 平台）固件与设备备份**，把「固件解包流」和「.nr 备份修改流」整合在一个三页签图形界面里，并提供完整的逆向打包能力。

- **页签① 固件解包**：扫描识别 → 剥压缩层 → 解 cpio → 切分区 → 解文件系统 → 找分区线索，支持一键智能解包
- **页签② NR 备份**：查看/校验设备网页导出的 `.nr` 备份，解包修改、重新打包，**一键制作开启 SSH/adbd 的解锁备份（两种注入方式可选）**
- **页签③ 逆向打包**：目录打 cpio/tar/压缩包、制作 JFFS2/squashfs 镜像、分区段拼接、**由 partitions 目录还原全量 fwtool 升级包**

核心解析（gzip/xz/lzma/bzip2/zstd、cpio newc、tar/zip、fwtool 尾、.nr 校验）全部内置，纯本地运行，不上传任何数据。

## 四、页签① 固件解包

### 4.1 路径区

- **固件文件**：选择待分析的固件/镜像（厂商全量升级 `.bin`、剥层产物、分区段等均可）。
- **输出目录**：选择文件后自动填为同目录下的 `<固件名>_unpack`，可改。

### 4.2 切段参数（给「2 剥一层压缩」和「4 切分区段」使用）

| 参数 | 含义 |
|---|---|
| 偏移 | 从文件哪个位置开始，支持 `0x` 十六进制与 `K/M/G`，如 `0x10000`、`2M` |
| 长度 | 切多少；`0` = 一直到文件尾 |
| 块大小 / skip块 / count块 | 按擦除块换算：起始 = skip × 块大小，长度 = count × 块大小（海思块大小一般 `0x20000` = 128K） |
| 按skip/count填充 | 点一下自动把 skip/count 换算填入偏移和长度 |

### 4.3 功能按钮（按解包流编号）

| 按钮 | 作用 | 主要产物（在输出目录内） |
|---|---|---|
| **1 扫描识别** | 文件头/尾 hex、全文件 magic 命中表（压缩/文件系统/镜像/归档）、gzip 成员信息、偏移 0 类型判定与下一步建议 | 仅日志 |
| **2 剥一层压缩** | 从指定偏移剥一层 gzip/xz/lzma-alone/bzip2/zstd，报告流后剩余字节（尾部数据）；gzip 带文件名时自动沿用 | `peeled_0x<偏移>.bin`，尾部元数据另存 `*.metadata.json` |
| **3 解包 cpio** | 解析 newc(070701)/crc(070702) cpio，支持串联成员 | `cpio_root/` |
| **4 切分区段** | 按偏移/长度切片 | `part_0x<偏移>.bin` |
| **5 解包文件系统** | 自动识别并解包 JFFS2/squashfs/UBI/ext4/cramfs/f2fs/erofs/romfs/tar/zip（外层压缩会自动剥） | `fs_root/` |
| **6 找分区线索** | 在镜像中搜索 ptable/xloader/hiboot/kernel/system/teeos 等段名与偏移 | 仅日志 |
| **7 分段裸包探测** | 探测分段全量镜像里的 gzip 成员、JFFS2、cpio 位置 | 仅日志 |
| **一键智能解包** | 全自动，见 4.4 | 见下 |

勾选「剥层完成后自动载入产物继续扫描」时，第 2 步完成会自动对剥出的文件再跑一次扫描识别。

### 4.4 一键智能解包（推荐首选）

点「**一键智能解包**」后，工具自动执行：压缩层逐层剥离（最多 8 层）→ 遇 cpio/tar/zip 解开 → 遇文件系统解包；识别为**厂商分段裸包**时，自动从 initramfs 的 `upgrade.sh` 解析段表、切出全部 11 个分区并解 rootfs。

典型产物结构（以 DD-5G / moses 固件为例）：

```
<固件名>_unpack/
├─ firmware.bin                    # 剥掉 fwtool 外壳后的分段内镜像（沿用 gzip 内文件名）
├─ firmware.bin.metadata.json      # 自动保存的升级包元数据（回包时默认复用）
├─ firmware.bin.fwtool_trailer.bin # fwtool 尾部（8 NUL + JSON + FWx0 校验块）
├─ kernel_Image.bin                # 从内核段导出的裸 Image（如有）
├─ initramfs_cpio.bin              # initramfs 的 cpio 衍生件（如有）
├─ initramfs/                      # 解包后的 initramfs 文件树
├─ partitions/                     # 按段表切出的全部分区段
│   ├─ xloader.bin  ptable.bin  mnvdload.bin  uce.bin
│   ├─ hiboot.bin   dts.bin     m3image.bin   teeos.bin
│   ├─ trusted_fw.bin  kernel.bin  system.bin  …
└─ system_rootfs/                  # system 段（JFFS2）解出的根文件系统 ★主要修改对象
```

> 手工用「2 剥一层压缩」时产物按偏移命名（如 `peeled_0x0.bin`）；gzip 头带文件名（厂商包均为 `firmware.bin`）时一键解包自动沿用该文件名。不同固件产物略有差异，日志会打印每一步的实际输出路径。

## 五、页签② NR 备份（.nr）

设备网页「备份/升级」导出的 `.nr` 文件结构为：NUL + ASCII 头部（name/size/crc/type）+ gzip(tar)，
其中 `crc = MD5("nradio_security_akxo1f\n" + gzip数据)`，工具已按设备 `/sbin/sysupgrade` 的真实算法还原。

### 5.1 路径区

- **.nr 备份文件**：选择设备导出的备份。
- **解包目录/打包源**：选择 `.nr` 后自动填 `<备份名>_unpacked`。
- **输出 .nr（可空）**：解锁时默认 `<备份名>-unlock.nr`；打包时默认 `<目录>-repacked.nr`。

### 5.2 功能按钮

| 按钮 | 作用 |
|---|---|
| **NR 查看信息+校验** | 解析头部字段并显示内部 tar 列表（含各文件权限），附带基本校验结果 |
| **NR 严格校验 verify** | 重新计算 MD5 与头部 crc 严格比对，判断备份是否损坏/被改过 |
| **NR 解包到目录** | 解开 gzip(tar) 到目录，可手工编辑里面的 `etc/config/*` 等文件 |
| **目录打包为 .nr** | 把目录重新打成 gzip(tar) 并生成新头部与正确 crc |
| **★ 一键制作解锁备份** | 见 5.3，**2.0 支持两种注入方式** |

### 5.3 ★ 一键制作解锁备份（最常用）

操作流程：

1. 设备网页「备份/升级」导出备份，得到 `.nr` 文件。
2. 在本页选好该文件。
3. 在「一键解锁选项」框中**选择注入方式**（方式一 / 方式二，见下）。
4. 方式一下可按需勾选「**同时取消隐藏 AT 指令页**」（默认勾选；该勾选框在方式二下自动禁用）。
5. 点「★ 一键制作解锁备份」，生成 `<原名>-unlock.nr`。
6. 在设备网页「备份/升级 → 恢复备份」上传该文件，设备校验通过后自动重启即生效。

两种方式的共同效果：**开放 LAN 侧 SSH（dropbear 22 端口，账号 root / 密码 admin）并启用 adbd（USB 调试）**，且都只在首次开机执行一次。

### 5.4 两种注入方式对比（2.0 新增）

| 对比项 | 方式一 uci-defaults（推荐，默认） | 方式二 rc.local（备选） |
|---|---|---|
| 写入位置 | `etc/uci-defaults/99-nr-unlock`（新增文件） | `etc/rc.local`（**合并**进已有脚本，不覆盖原命令） |
| 执行时机 | 开机时由系统统一执行 uci-defaults 脚本 | 开机流程**末尾**（rc.local）执行 |
| 生效方式 | 写入 uci 配置，依赖后续服务重启生效 | `uci commit` 后**立即** reload 防火墙 / start adbd |
| 一次性原理 | OpenWrt 在脚本**执行成功后自动删除**该脚本 | 块尾 `sed -i … /etc/rc.local` **自删除注入块** |
| 取消隐藏 AT 指令页 | 支持（勾选生效，AT 页二次密码 `admin@0515`） | **不支持**（仅 SSH + adbd） |
| 备份内原本没有该文件 | 直接新建 | 自动新建 `etc/rc.local`（补 `#!/bin/sh`，权限 0755） |
| 重复点击解锁 | 固定脚本内容，无副作用 | **幂等**：每次先去重旧注入块，再插入新块，始终只有一块 |
| 适用场景 | 绝大多数设备，优先使用 | 设备不执行/不清理 uci-defaults、或希望开机末尾立即生效时备选 |

**方式二 rc.local 注入块做了什么（了解即可，无需手工干预）：**

```sh
# >>> nr-tool-unlock-begin >>>          ← 唯一开始标记
{
    uci -q delete firewall.ssh           # 先删旧规则，避免重复
    uci set firewall.ssh=rule            # 新建 LAN→22/tcp ACCEPT 规则
    uci set firewall.ssh.name='Allow-SSH'
    uci set firewall.ssh.src='lan'
    uci set firewall.ssh.family='ipv4'
    uci set firewall.ssh.proto='tcp'
    uci set firewall.ssh.dest_port='22'
    uci set firewall.ssh.target='ACCEPT'
    uci set adbd.service.enable='1'      # 启用 adbd
    uci commit firewall
    uci commit adbd
    /etc/init.d/firewall reload || restart
    /etc/init.d/adbd start || restart
    sed -i '/nr-tool-unlock-begin/,/nr-tool-unlock-end/d' /etc/rc.local  # 自删除
}
# <<< nr-tool-unlock-end <<<            ← 唯一结束标记
```

注入块会插入到 rc.local 中**最后一个 `exit 0` 之前**；没有 `exit 0` 时自动补一个；换行统一为 LF；不会删除或覆盖你原有的任何自定义命令。

> 两种方式产物都能通过「NR 严格校验 verify」；方式二产物的 tar 列表中 `etc/rc.local` 权限为 755，且不会出现 `etc/uci-defaults/99-nr-unlock`，可用「NR 解包到目录」自行核对。

## 六、页签③ 逆向打包（解包流的反向操作）

### 6.1 路径与选项

- **源目录（归档/镜像）**：打 cpio/tar/jffs2/squashfs/fwtool 时选择。
- **源文件（压缩包裹）**：单文件压缩时选择。
- **输出路径（可空）**：留空则按默认名生成在源目录旁。
- **fwtool 元数据（可空）**：见 6.2 最后一项，留空自动查找。
- **压缩格式**：none/gzip/xz/lzma/bz2/zstd（打 cpio/tar、压缩包裹时用）。
- **JFFS2 擦除块**：默认 `0x20000`（128K）。
- **squashfs 压缩**：xz/gzip/lzma/zstd/lzo（传给外部 mksquashfs）。
- **拼接填充块**：分区拼接时按该块大小用 `0xFF` 填充对齐，`0` = 不填充；海思分段用 `0x20000`。

### 6.2 功能按钮

| 按钮 | 作用 | 默认产物名 |
|---|---|---|
| **目录→cpio (+压缩)** | 纯 Python 生成 newc cpio（4 字节对齐、TRAILER、512 块补齐），可再套压缩 | `<目录>.cpio[.gz/.xz…]` |
| **目录→tar (+压缩)** | GNU tar，保留目录、符号链接、权限，可选压缩 | `<目录>.tar[.gz…]` |
| **文件→压缩包裹** | gzip（mtime=0，仿真设备）/xz/lzma/bzip2/zstd | 源文件名加对应后缀 |
| **目录→JFFS2 镜像** | 调外部 `mkfs.jffs2`（通常在 WSL 内） | `<目录>.jffs2` |
| **目录→squashfs 镜像** | 调外部 `mksquashfs` | `<目录>.squashfs` |
| **分区段拼接为整镜像** | 弹窗**按顺序多选**分区段文件，依次拼接，可选块填充 | `joined_fullflash.bin` |
| **★ 分区→fwtool 升级包** | 见下 | `<固件名>.repack.bin` |

**★ fwtool 升级包**是「一键智能解包」的逆过程：

1. 源目录选一键解包产出的 **`partitions` 目录**（含 11 个 `<段名>.bin`）；
2. 工具按 moses 段表（xloader/ptable/mnvdload/uce/hiboot/dts/m3image/teeos/trusted_fw/kernel/system）拼内镜像；
3. gzip 压缩（带 `firmware.bin` 文件名标记，与厂商风格一致）；
4. 追加 8 个 NUL + 元数据 JSON + `FWx0` 校验尾（CRC32 自动重算）。
5. 元数据留空时，优先自动复用解包时保存的 `firmware.bin.metadata.json`，找不到才用内置默认值。

> **段长约束**：除尾段 `system` 外，其余 10 个固定段长度必须与段表一致（块数×0x20000），否则工具直接报错——固定段改长改短都会导致后续所有段偏移错位。

## 七、典型工作流

### 流程 A：解包 → 改 rootfs → 封回可刷的全量升级包

1. 页签① 选固件，点「**一键智能解包**」。
2. 修改输出目录里的 `system_rootfs/`（如 `etc/config/*` 配置、脚本）。
3. **重建 system 段**（JFFS2 需外部工具，一般在 WSL 内执行，日志也会给出命令）：
   `mkfs.jffs2 -r system_rootfs -o partitions/system.bin -e 0x20000 -n`
4. 页签③ 源目录选 `partitions/`，元数据留空，点「**★ 分区→fwtool 升级包**」，得到 `<固件名>.repack.bin`。
5. 按设备原方式刷入/网页升级。

### 流程 B：开启设备 SSH / adbd（最常用）

见 5.3：网页导出 .nr → 选注入方式（默认方式一即可）→ ★一键制作解锁备份 → 网页恢复，全程不到一分钟。若恢复后方式一生效不明显，可改选**方式二 rc.local** 重新制作再试。

### 流程 C：手工分析不明镜像

「1 扫描识别」看 magic 与建议 →「2 剥一层压缩」逐层深入（勾选自动继续扫描）→「6 找分区线索」/「7 分段裸包探测」定位 →「4 切分区段」或「3 解包 cpio」/「5 解包文件系统」定点处理。

### 流程 D：解包 .nr 手工改配置后原样封回

页签②「NR 解包到目录」→ 编辑 `<备份名>_unpacked/etc/config/*` →「目录打包为 .nr」→ 网页恢复。此流程不注入任何解锁脚本，仅用于改配置。

## 八、外部程序依赖边界（重要）

exe 已内置 Python 运行时、zstandard 以及全部压缩/归档/fwtool/.nr 能力，但以下**文件系统**操作依赖系统 PATH 中的**外部程序**，在未安装的电脑上对应步骤会按原设计报「未找到 xxx」：

| 功能 | 需要的外部程序 | 安装/获取方式 |
|---|---|---|
| JFFS2 解包 | `jefferson` | `pip install jefferson`（用源码版同解释器时） |
| squashfs 解包 | `unsquashfs`/`sasquatch`，或 **7-Zip** | 安装 7-Zip 后自动兜底（非标准压缩可能失败） |
| ext4/cramfs/f2fs/erofs/romfs | **7-Zip**（或 WSL 挂载） | 安装 7-Zip |
| UBI 解包 | `ubireader_extract_files` | `pip install ubi_reader` |
| 制作 JFFS2 镜像 | `mkfs.jffs2` | mtd-utils，一般在 **WSL/Linux** 内 |
| 制作 squashfs 镜像 | `mksquashfs` | squashfs-tools，一般在 **WSL/Linux** 内 |

**纯内置、无外部依赖**的部分：扫描识别、全部压缩剥层/压缩（含 zstd）、cpio/tar/zip、分段切段与探测、.nr 全套（查看/校验/解包/打包/两种解锁）、分区拼接、fwtool 升级包制作。

## 九、注意事项

1. **刷机/恢复备份有变砖风险**，请确认设备具备救砖手段后再操作，风险自负。
2. 改 rootfs 后回包，**只有尾段 system 长度可变**；其余分区段必须保持原长（工具会强制校验）。
3. 固定段（内核、hiboot、teeos、trusted_fw 等）非必要不要修改。
4. 「一键解锁备份」会开放 SSH（root/admin）与 adbd，**仅限自用可信网络环境**；用完建议及时关闭或改密。方式二执行后注入块会自删除，但**开放的配置会保留**，如需关闭要手工改回 uci。
5. 方式二只动 `etc/rc.local`，**不要**在解锁前手工往 rc.local 里写同名标记 `nr-tool-unlock-begin/end`；工具靠这对标记去重。
6. 工具**不会删除**已有的解包目录；重复解 JFFS2 时 `jefferson` 要求目标不存在，工具会先清掉对应的旧 `fs_root/system_rootfs` 目录再解，请勿把自己的其他文件放进这些目录。
7. 所有产物默认生成在固件/备份旁边的 `_unpack`、`_unpacked` 目录，留意磁盘空间（整镜像解包可能较大）。
8. 单文件 exe 运行时会在系统临时目录（`%TEMP%`）自解压，属正常现象；安全软件偶尔误报，可加白名单。

## 十、命令行模式（CLI，可选）

需要脚本化批量处理时可使用 CLI。两种途径：

- **源码（推荐用于交互式命令行）**：本机装有 Python 3 时
  `python 固件解包工具2.0.py --cli <子命令> [参数]`
- **exe 本身也支持 `--cli`**：因 GUI 版 exe 不挂控制台，建议**重定向输出**查看结果，例如：
  `固件解包工具2.0.exe --cli nr-verify backup.nr > out.txt 2>&1`

### 10.1 子命令一览

| 分类 | 子命令 |
|---|---|
| 解包流 | `scan` / `peel` / `cpio` / `split` / `fs` / `parts` / `probe` / `auto` |
| NR | `nr-info` / `nr-verify` / `nr-unpack` / `nr-pack` / `nr-unlock` |
| 逆向打包 | `pack-cpio` / `pack-tar` / `compress` / `mkfs` / `join` / `pack-fwtool` |

任一子命令加 `-h` 可查看其完整参数。

### 10.2 常用示例

```bat
# 一键智能解包
python 固件解包工具2.0.py --cli auto firmware.bin -o firmware_unpack

# NR 查看 / 严格校验 / 解包
python 固件解包工具2.0.py --cli nr-info backup.nr
python 固件解包工具2.0.py --cli nr-verify backup.nr
python 固件解包工具2.0.py --cli nr-unpack backup.nr -d backup_unpacked

# NR 重新打包
python 固件解包工具2.0.py --cli nr-pack backup_unpacked -o new.nr

# ★ 解锁备份 —— 方式一 uci-defaults（默认，含 AT 页）
python 固件解包工具2.0.py --cli nr-unlock backup.nr -o unlock.nr
# 方式一但不显示 AT 页
python 固件解包工具2.0.py --cli nr-unlock backup.nr --no-at -o unlock.nr
# ★ 方式二 rc.local 开机一次性脚本（仅 SSH+adbd，忽略 --no-at）
python 固件解包工具2.0.py --cli nr-unlock backup.nr --method rc -o unlock-rc.nr

# 目录打 cpio.gz / tar.gz
python 固件解包工具2.0.py --cli pack-cpio initramfs_dir -o initramfs.cpio.gz --compress gzip
python 固件解包工具2.0.py --cli pack-tar rootfs_dir -o rootfs.tar.gz --compress gzip

# 单文件压缩（gzip/xz/lzma/bz2/zstd）
python 固件解包工具2.0.py --cli compress data.bin --format zstd -o data.bin.zst

# 分区拼接（0x20000 块填充）/ partitions 目录还原 fwtool 全量升级包
python 固件解包工具2.0.py --cli join xloader.bin ptable.bin ... system.bin -o fullflash.bin --pad-block 0x20000
python 固件解包工具2.0.py --cli pack-fwtool firmware_unpack\partitions -o repack.bin
```

### 10.3 nr-unlock 参数

| 参数 | 取值 | 说明 |
|---|---|---|
| `nr`（位置参数） | 文件路径 | 设备导出的原始 `.nr` 备份 |
| `-o, --out` | 路径 | 输出文件；留空默认 `<原名>-unlock.nr` |
| `--method` | `uci`（默认）/ `rc` | `uci` = 注入 uci-defaults；`rc` = 注入 rc.local 一次性脚本 |
| `--no-at` | 开关 | 仅方式一生效：不写入「取消隐藏 AT 指令页」逻辑；SSH+adbd 始终开启 |

## 十一、常见问题

**Q：双击 exe 没反应/很久才出窗口？**
A：单文件版首次启动要自解压，等十几秒正常；若被杀毒软件拦截请加白名单，任务管理器里能看到进程即代表正在启动。

**Q：日志报「未找到 jefferson / unsquashfs / 7-Zip」？**
A：该步骤依赖外部程序，见第八章。压缩剥层、cpio、.nr（含两种解锁）、fwtool 等核心功能不受影响。

**Q：一键智能解包提示「无法继续自动识别」？**
A：镜像没有已知 magic 且不符合分段裸包特征。先用「6 找分区线索」「7 分段裸包探测」定位，或检查 `initramfs/` 里 `upgrade.sh` 的段表定义，再手工「4 切分区段」。

**Q：封 fwtool 时报某段「长度与段表定义不符」？**
A：除 `system` 尾段外的固定分区段不能改变长度。请用 `partitions/` 目录里未改动的原段，只替换重建后的 `system.bin`。

**Q：-unlock.nr 恢复后 SSH 连不上？**
A：先确认与设备 LAN 口同网段、22 端口未被上游网络拦截、设备已正常重启；账号 root / 密码 admin。若**方式一**不生效，改用**方式二 rc.local**（开机末尾 `uci commit` 后立即 reload/start）重新制作备份再恢复一次。

**Q：方式二会不会破坏我 rc.local 里原有的命令？**
A：不会。工具只在一对唯一标记之间插入/替换注入块，原内容逐行保留；没有 `exit 0` 或缺 `#!/bin/sh` 时会自动补齐，执行一次后注入块自删除，恢复成接近原样的 rc.local。

**Q：方式二为什么没有 AT 指令页选项？**
A：AT 页逻辑只随方式一的 uci-defaults 脚本提供；方式二设计为最小化、仅开启 SSH + adbd 的开机末尾一次性脚本，因此选中方式二时该勾选框会自动置灰。

**Q：同一份备份反复点了好几次解锁，会不会注入很多段？**
A：方式二是幂等的——每次打包都会先剔除旧的 `nr-tool-unlock` 标记块再插入，最终 tar 内永远只有一块；方式一写入的是固定文件名脚本，重复也只有一份。

**Q：NR 严格校验失败？**
A：头部 crc 与重新计算的 MD5 不一致，说明文件已损坏或被其他工具改动过；重新从设备导出原始备份再操作。本工具生成的解锁/重打包文件均会重算正确 crc，正常应 PASS。
