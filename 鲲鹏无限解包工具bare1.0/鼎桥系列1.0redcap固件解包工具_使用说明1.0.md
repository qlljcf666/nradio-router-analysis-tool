# 固件 / NR 备份 可视化解包-打包工具 使用说明

版本：bare 1.0（单文件 exe）
适用平台：Windows（64 位）

---

## 一、工具简介

本工具面向**鲲鹏无限（NRadio / DD-5G 类 moses 平台）固件与设备备份**，把「固件解包流」和「.nr 备份修改流」整合在一个三页签图形界面里，并提供完整的逆向打包能力。

- **页签① 固件解包**：扫描识别 → 剥压缩层 → 解 cpio → 切分区 → 解文件系统 → 找分区线索，支持一键智能解包
- **页签② NR 备份**：查看/校验设备网页导出的 `.nr` 备份，解包修改、重新打包，**一键制作开启 SSH/adbd 的解锁备份**
- **页签③ 逆向打包**：目录打 cpio/tar/压缩包、制作 JFFS2/squashfs 镜像、分区段拼接、**由 partitions 目录还原全量 fwtool 升级包**

核心解析（gzip/xz/lzma/bzip2/zstd、cpio newc、tar/zip、fwtool 尾、.nr 校验）全部内置，纯本地运行。

## 四、页签① 固件解包

### 4.1 路径区

- **固件文件**：选择待分析的固件/镜像（厂商全量升级 `.bin`、剥层产物、分区段等均可）。
- **输出目录**：选择文件后自动填为同目录下的 `<固件名>_unpack`，可改。

### 4.2 切段参数（给「2 剥一层压缩」和「4 切分区段」使用）

| 参数 | 含义 |
|---|---|
| 偏移 | 从文件哪个位置开始，支持 `0x` 十六进制与 `K/M/G`，如 `0x10000`、`2M` |
| 长度 | 切多少；`0` = 一直到文件尾 |
| 块大小 / skip块 / count块 | 按擦除块换算：起始 = skip × 块大小，长度 = count × 块大小（海思块大小一般 `0x20000`=128K） |
| 按skip/count填充 | 点一下自动把 skip/count 换算填入偏移和长度 |

### 4.3 功能按钮（按解包流编号）

| 按钮 | 作用 | 主要产物（在输出目录内） |
|---|---|---|
| **1 扫描识别** | 文件头/尾 hex、全文件 magic 命中表（压缩/文件系统/镜像/归档）、gzip 成员信息、偏移 0 类型判定与下一步建议 | 仅日志 |
| **2 剥一层压缩** | 从指定偏移剥一层 gzip/xz/lzma-alone/bzip2/zstd，并报告流后剩余字节（尾部数据）；gzip 带文件名时自动沿用 | `peeled_0x<偏移>.bin`，尾部元数据另存 `*.metadata.json` |
| **3 解包 cpio** | 解析 newc(070701)/crc(070702) cpio，支持串联成员 | `cpio_root/` |
| **4 切分区段** | 按偏移/长度切片 | `part_0x<偏移>.bin` |
| **5 解包文件系统** | 自动识别并解包 JFFS2/squashfs/UBI/ext4/cramfs/f2fs/erofs/romfs/tar/zip（外层压缩会自动剥） | `fs_root/` |
| **6 找分区线索** | 在镜像中搜索 ptable/xloader/hiboot/kernel/system/teeos 等段名与偏移 | 仅日志 |
| **7 分段裸包探测** | 探测分段全量镜像里的 gzip 成员、JFFS2、cpio 位置 | 仅日志 |
| **一键智能解包** | 全自动，见 4.4 | 见下 |

勾选「剥层完成后自动载入产物继续扫描」时，第 2 步完成会自动对剥出的文件再跑一次扫描识别。

### 4.4 一键智能解包（推荐首选）

点「**一键智能解包**」后，工具自动执行：压缩层逐层剥离（最多 8 层）→ 遇 cpio/tar/zip 解开 → 遇文件系统解包；识别为**厂商分段裸包**时，自动从 initramfs 的 `upgrade.sh` 解析段表、切出全部 11 个分区并解 rootfs。

典型产物结构（以 DD-5G / moses 固件为例）：

```
<固件名>_unpack/
├─ firmware.bin                    # 剥掉 fwtool 外壳后的分段内镜像（沿用 gzip 内文件名）
├─ firmware.bin.metadata.json      # 自动保存的升级包元数据（回包时默认复用）
├─ firmware.bin.fwtool_trailer.bin # fwtool 尾部（8 NUL + JSON + FWx0 校验块）
├─ kernel_Image.bin                # 从内核段导出的裸 Image（如有）
├─ initramfs_cpio.bin              # initramfs 的 cpio 衍生件（如有）
├─ initramfs/                      # 解包后的 initramfs 文件树
├─ partitions/                     # 按段表切出的全部分区段
│   ├─ xloader.bin  ptable.bin  mnvdload.bin  uce.bin
│   ├─ hiboot.bin   dts.bin     m3image.bin   teeos.bin
│   ├─ trusted_fw.bin  kernel.bin  system.bin  …
└─ system_rootfs/                  # system 段（JFFS2）解出的根文件系统 ★主要修改对象
```

> 手工用「2 剥一层压缩」时产物按偏移命名（如 `peeled_0x0.bin`）；gzip 头带文件名（厂商包均为 `firmware.bin`）时一键解包自动沿用该文件名。不同固件产物略有差异，日志会打印每一步的实际输出路径。

## 五、页签② NR 备份（.nr）

设备网页「备份/升级」导出的 `.nr` 文件结构为：NUL + ASCII 头部（name/size/crc/type）+ gzip(tar)，
其中 `crc = MD5("nradio_security_akxo1f\n" + gzip数据)`，工具已按设备 `/sbin/sysupgrade` 的真实算法还原。

### 5.1 路径区

- **.nr 备份文件**：选择设备导出的备份。
- **解包目录/打包源**：选择 `.nr` 后自动填 `<备份名>_unpacked`。
- **输出 .nr（可空）**：自动填 `<备份名>-unlock.nr`。

### 5.2 功能按钮

| 按钮 | 作用 |
|---|---|
| **NR 查看信息+校验** | 解析头部字段并显示内部 tar 列表，附带基本校验结果 |
| **NR 严格校验 verify** | 重新计算 MD5 与头部 crc 严格比对，判断备份是否损坏/被改过 |
| **NR 解包到目录** | 解开 gzip(tar) 到目录，可手工编辑里面的 `etc/config/*` 等文件 |
| **目录打包为 .nr** | 把目录重新打成 gzip(tar) 并生成新头部与正确 crc（默认名 `<目录>-repacked.nr`） |
| **★ 一键制作解锁备份** | 见 5.3 |

### 5.3 ★ 一键制作解锁备份（最常用）

1. 设备网页导出备份，得到 `.nr` 文件。
2. 本页选好该文件，按需勾选「**同时取消隐藏 AT 指令页**」（默认勾选；不改可取消）。
3. 点「★ 一键制作解锁备份」，生成 `<原名>-unlock.nr`。

工具向备份内注入 `etc/uci-defaults/99-nr-unlock` 开机脚本，设备恢复备份、首次开机时自动执行一次并自删，效果：

1. 开放 **LAN 侧 SSH（dropbear 22 端口，root / admin）** 防火墙规则；
2. 启用 **adbd**（USB 调试）；
3. （勾选时）显示隐藏的 **AT 指令页**（该页二次密码 `admin@0515`）。

随后在设备网页「备份/升级 → 恢复备份」上传该 `-unlock.nr`，设备校验通过后自动重启即生效。

## 六、页签③ 逆向打包（解包流的反向操作）

### 6.1 路径与选项

- **源目录（归档/镜像）**：打 cpio/tar/jffs2/squashfs/fwtool 时选择。
- **源文件（压缩包裹）**：单文件压缩时选择。
- **输出路径（可空）**：留空则按默认名生成在源目录旁。
- **fwtool 元数据（可空）**：见 6.2 最后一项，留空自动查找。
- **压缩格式**：none/gzip/xz/lzma/bz2/zstd（打 cpio/tar、压缩包裹时用）。
- **JFFS2 擦除块**：默认 `0x20000`（128K）。
- **squashfs 压缩**：xz/gzip/lzma/zstd/lzo（传给外部 mksquashfs）。
- **拼接填充块**：分区拼接时按该块大小用 `0xFF` 填充对齐，`0` = 不填充；海思分段用 `0x20000`。

### 6.2 功能按钮

| 按钮 | 作用 | 默认产物名 |
|---|---|---|
| **目录→cpio (+压缩)** | 纯 Python 生成 newc cpio（4 字节对齐、TRAILER、512 块补齐），可再套压缩 | `<目录>.cpio[.gz/.xz…]` |
| **目录→tar (+压缩)** | GNU tar，保留目录、符号链接、权限，可选压缩 | `<目录>.tar[.gz…]` |
| **文件→压缩包裹** | gzip（mtime=0，仿真设备）/xz/lzma/bz2/zstd | 源文件名加对应后缀 |
| **目录→JFFS2 镜像** | 调外部 `mkfs.jffs2`（通常在 WSL 内） | `<目录>.jffs2` |
| **目录→squashfs 镜像** | 调外部 `mksquashfs` | `<目录>.squashfs` |
| **分区段拼接为整镜像** | 弹窗**按顺序多选**分区段文件，依次拼接，可选块填充 | `joined_fullflash.bin` |
| **★ 分区→fwtool 升级包** | 见下 | `<固件名>.repack.bin` |

**★ fwtool 升级包**是「一键智能解包」的逆过程：

1. 源目录选一键解包产出的 **`partitions` 目录**（含 11 个 `<段名>.bin`）；
2. 工具按 moses 段表（xloader/ptable/mnvdload/uce/hiboot/dts/m3image/teeos/trusted_fw/kernel/system）拼内镜像；
3. gzip 压缩（带 `firmware.bin` 文件名标记，与厂商风格一致）；
4. 追加 8 个 NUL + 元数据 JSON + `FWx0` 校验尾（CRC32 自动重算）。
5. 元数据留空时，优先自动复用解包时保存的 `peeled_0x0.bin.metadata.json`，找不到才用内置默认值。

> **段长约束**：除尾段 `system` 外，其余 10 个固定段长度必须与段表一致（块数×0x20000），否则工具直接报错——固定段改长改短都会导致后续所有段偏移错位。

## 七、典型工作流

### 流程 A：解包 → 改 rootfs → 封回可刷的全量升级包

1. 页签① 选固件，点「**一键智能解包**」。
2. 修改输出目录里的 `system_rootfs/`（如 `etc/config/*` 配置、脚本）。
3. **重建 system 段**（JFFS2 需外部工具，一般在 WSL 内执行，日志也会给出命令）：
   `mkfs.jffs2 -r system_rootfs -o partitions/system.bin -e 0x20000 -n`
4. 页签③ 源目录选 `partitions/`，元数据留空，点「**★ 分区→fwtool 升级包**」，得到 `<固件名>.repack.bin`。
5. 按设备原方式刷入/网页升级。

### 流程 B：开启设备 SSH / adbd

见 5.3：导出 .nr → ★一键制作解锁备份 → 网页恢复，全程不到一分钟。

### 流程 C：手工分析不明镜像

「1 扫描识别」看 magic 与建议 →「2 剥一层压缩」逐层深入（勾选自动继续扫描）→「6 找分区线索」/「7 分段裸包探测」定位 →「4 切分区段」或「3 解包 cpio」/「5 解包文件系统」定点处理。

## 八、外部程序依赖边界（重要）

exe 已内置全部压缩/归档/fwtool/.nr 能力，但以下文件系统操作依赖系统 PATH 中的**外部程序**，在未安装的电脑上对应步骤会按原设计报「未找到 xxx」：

| 功能 | 需要的外部程序 | 安装/获取方式 |
|---|---|---|
| JFFS2 解包 | `jefferson` | `pip install jefferson`（本工具源码版同解释器下） |
| squashfs 解包 | `unsquashfs`/`sasquatch`，或 **7-Zip** | 安装 7-Zip 后自动兜底（非标准压缩可能失败） |
| ext4/cramfs/f2fs/erofs/romfs | **7-Zip**（或 WSL 挂载） | 安装 7-Zip |
| UBI 解包 | `ubireader_extract_files` | `pip install ubi_reader` |
| 制作 JFFS2 镜像 | `mkfs.jffs2` | mtd-utils，一般在 **WSL/Linux** 内 |
| 制作 squashfs 镜像 | `mksquashfs` | squashfs-tools，一般在 **WSL/Linux** 内 |

纯内置、无外部依赖的部分：扫描识别、全部压缩剥层/压缩、cpio/tar/zip、分段切段与探测、.nr 全套、分区拼接、fwtool 升级包制作。

## 九、注意事项

1. **刷机/恢复备份有变砖风险**，请确认设备具备救砖手段后再操作，风险自负。
2. 改 rootfs 后回包，**只有尾段 system 长度可变**；其余分区段必须保持原长（工具会强制校验）。
3. 固定段（内核、hiboot、teeos、trusted_fw 等）非必要不要修改。
4. 「一键解锁备份」会开放 SSH（root/admin）与 adbd，**仅限自用可信网络环境**；用完建议及时关闭或改密。
5. 工具**不会删除**已有的解包目录；重复解 JFFS2 时 `jefferson` 要求目标不存在，工具会先清掉对应的旧 `fs_root/system_rootfs` 目录再解，请勿把自己的其他文件放进这些目录。
6. 所有产物默认生成在固件/备份旁边的 `_unpack`、`_unpacked` 目录，留意磁盘空间（整镜像解包可能较大）。

## 十、命令行模式（可选，需用 .py 源码）

exe 为纯图形界面。如需脚本化批量处理，可用源码运行 CLI（本机需装 Python 3）：

```
python 固件解包工具.py --cli <子命令> [参数]
```

支持的子命令：

- 解包流：`scan` / `peel` / `cpio` / `split` / `fs` / `parts` / `probe` / `auto`
- NR：`nr-info` / `nr-verify` / `nr-unpack` / `nr-pack` / `nr-unlock`
- 打包：`pack-cpio` / `pack-tar` / `compress` / `mkfs` / `join` / `pack-fwtool`

示例：`python 固件解包工具.py --cli auto firmware.bin -o firmware_unpack`
（各子命令参数可用 `-h` 查看。）

## 十一、常见问题

**Q：双击 exe 没反应/很久才出窗口？**
A：单文件版首次启动要自解压，等十几秒正常；若被杀毒软件拦截请加白名单。

**Q：日志报「未找到 jefferson / unsquashfs / 7-Zip」？**
A：该步骤依赖外部程序，见第八章。压缩剥层、cpio、.nr、fwtool 等核心功能不受影响。

**Q：一键智能解包提示「无法继续自动识别」？**
A：镜像没有已知 magic 且不符合分段裸包特征。先用「6 找分区线索」「7 分段裸包探测」定位，或检查 `initramfs/` 里 `upgrade.sh` 的段表定义，再手工「4 切分区段」。

**Q：封 fwtool 时报某段「长度与段表定义不符」？**
A：除 `system` 尾段外的固定分区段不能改变长度。请用 `partitions/` 目录里未改动的原段，只替换重建后的 `system.bin`。

**Q：-unlock.nr 恢复后 SSH 连不上？**
A：确认与设备 LAN 口同网段、22 端口未被上游网络拦截；设备需已正常重启且开机脚本执行（执行一次后自删）。账号 root / admin。

**Q：NR 严格校验失败？**
A：头部 crc 与重新计算的 MD5 不一致，说明文件已损坏或被其他工具改动过；重新从设备导出原始备份再操作。
