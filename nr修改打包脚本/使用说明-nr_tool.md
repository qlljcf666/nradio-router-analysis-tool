# NRadio DD-5G .nr 备份 图形化修改/打包工具 使用说明

版本：单文件 exe（含图形界面）
适用设备：鲲鹏无限 NRadio DD-5G（WT2967 / Hi6352），固件 2.1.11 / 2.2.15（OpenWrt / BusyBox）
适用平台：Windows 64 位，**无需安装 Python**

---

## 一、工具简介

本工具处理设备网页「备份/升级」导出的 **`.nr` 配置备份**，提供四个图形化功能：

1. **一键解锁备份**：在备份中注入开机配置，恢复后自动开启 **SSH** 与 **ADB(adbd)**（含两种注入方式，见第五章）；
2. **查看信息 / 严格校验**：解析备份头部、核对 CRC 签名、列出包内文件；
3. **解包 .nr**：解开成普通文件夹，可手工改任意配置；
4. **目录重新打包**：把改好的文件夹重新打成设备可接受的 `.nr`，自动重算 CRC。

核心校验逻辑为逆向设备 `/sbin/sysupgrade` 得到，生成的备份可直接通过网页「恢复备份」上传。

## 三、.nr 文件是什么（背景知识）

`.nr` 是设备的配置备份，内部结构（逆向确认）：

```
偏移 0   : 1 字节 0x00
偏移 1   : 一行 ASCII 头部，以 \n 结束
           name=- size=<gzip字节数> crc=<MD5> type=config
其后     : 完整 gzip(tar) 数据（gzip mtime=0）
```

- 包内是一个 tar，装着 `etc/config/*` 等配置文件；
- **CRC = MD5( 固定盐 `nradio_security_akxo1f` + 换行 + gzip 数据 )**，设备恢复时会严格校验；
- 因此凡是手工改动包内容，都必须用本工具（或相同算法）**重新计算 CRC**，否则设备拒绝恢复。

**为什么需要"开机注入"：** 设备恢复备份时会主动丢弃包内的 `etc/config/firewall` 与 `etc/config/adbd`，所以直接改这两个文件无效；必须在开机阶段由脚本重新建立配置。本工具提供两种开机注入方式。

## 五、页签① 一键解锁（核心功能）

### 5.1 操作步骤

1. 「.nr 备份文件」点「浏览…」选择设备导出的原始备份；
2. 「输出文件」**可留空**：默认生成在原备份同目录，名为 `<原名>-unlock.nr`；也可自行指定；
3. 在「注入方式」框中**二选一**（见 5.2）；
4. 方式一可用时，按需勾选「同时取消隐藏 AT 指令页」（选方式二时该选项自动变灰）；
5. 点「**★ 一键制作解锁备份**」，日志区显示过程，完成后到网页恢复。

### 5.2 两种注入方式对比

| 项目 | 方式一 uci-defaults（默认/推荐） | 方式二 rc.local |
|---|---|---|
| 写入文件 | `etc/uci-defaults/99-nr-unlock`（新增独立脚本） | 合并进已有的 `etc/rc.local` |
| 执行时机 | 开机时由 `/etc/init.d/boot` 调用 | 开机流程**末尾**由 procd 执行 |
| 开启内容 | SSH + ADB（+ 可选 AT 页） | **仅 SSH + ADB** |
| 生效动作 | 系统随后统一 commit/reload | 脚本内主动 `uci commit` 并立即 reload firewall、start adbd |
| 一次性 | 系统执行成功后**自动删除**该脚本 | 块尾用 `sed` **自我删除注入块**，之后开机不再执行 |
| 对原文件影响 | 只新增一个文件 | 保留 `rc.local` 原有内容，注入块插在 `exit 0` 之前 |

**两种方式开启的服务相同：**

- **SSH**：在 firewall 建立名为 `ssh` 的 LAN→ACCEPT 规则，TCP 22 端口（dropbear）；登录账号 **root / admin**；
- **ADB**：`uci set adbd.service.enable='1'`，开启 USB 调试 adbd。

**差异点：**

- 方式一额外支持「取消隐藏 AT 指令页」（仅出厂 oem 标记为 `odm` 的设备生效，该页面二次密码 `admin@0515`）；方式二不含此项；
- 若设备上 uci-defaults 机制异常，可换方式二（rc.local 在启动更晚阶段、主动 commit 并立即拉起服务）作为备选。

### 5.3 恢复方法与效果确认

1. 设备登录网页 →「备份/升级」→「恢复备份」→ 选择生成的 `-unlock.nr`；
2. 设备校验 CRC 通过后自动重启；
3. 首次开机注入脚本执行（随后自删）：
   - 用网线把电脑接到 LAN 口、同网段下，尝试 SSH 连接 `192.168.x.1` 的 22 端口，root/admin；
   - USB 连接后可用 `adb devices` 看到设备。

## 六、页签② 查看信息 / 严格校验

- 选择 `.nr` 文件后：
  - **查看信息**：在下方文本框显示 `name/type`、头部声称 size 与实际 gzip 长度、声称 CRC 与实算 CRC、tar 完整性、包内每个文件的类型/权限/大小/路径；
  - **严格校验 verify**：同时检查 ① size 字段、② CRC（盐 `nradio_security_akxo1f`）、③ gzip/tar 是否可正常解开；
    - 全部通过显示绿色 PASS，表示设备 `sysupgrade --valid-tag` 可接受；
    - 任一失败弹错误框、日志红色提示（常见原因：文件被其他工具改过但未重算 CRC、传输损坏）。

## 七、页签③ 解包 与 页签④ 打包（手工修改流程）

### 7.1 解包（页签③）

- 选择 `.nr` 备份；目标目录**可留空**，默认解到同目录 `<备份名>_unpacked`；
- 目标目录必须**不存在或为空目录**，否则报错（防止覆盖）；
- 解出的结构即设备内相对路径，如 `etc/config/network`、`etc/config/wireless` 等，可直接用文本编辑器修改。

### 7.2 重新打包（页签④）

- 「解包后的目录」选 7.1 解出的文件夹，选好后会自动填默认输出名 `<目录名>-repacked.nr`；
- 指定输出 `.nr` 路径，点「打包为 .nr（自动算 crc）」；
- 打包规则（复刻设备风格）：
  - 仅打包文件与符号链接，POSIX 相对路径，属主 root:root；
  - gzip(tar)，mtime=0、OS 字段仿 Unix；
  - 自动可执行权限 0755：`etc/uci-defaults/`、`etc/init.d/`、`bin/sbin/usr/bin/usr/sbin` 下脚本、`etc/rc.local` 等，其余 0644；符号链接 0777；
  - 自动重算 CRC，产物可直接网页恢复。

> 建议：只是想开 SSH/ADB，用页签①即可，无需手工解包；页签③④用于修改其它配置（如网络、无线参数）。

## 八、命令行方式（用随附 .cmd / 源码）

图形 exe 不提供文本输出；需要批处理时，在已安装 Python 3 的电脑上用源码（两个 .cmd 已封装好）：

```
python nr_tool.py <子命令> [参数]
```

| 子命令 | 作用 |
|---|---|
| `info <in.nr>` | 查看头部 / CRC / 列文件 |
| `verify <in.nr>` | 严格校验，失败返回退出码 1 |
| `unpack <in.nr> [-d 目录]` | 解包（默认 `<名>_unpacked`） |
| `pack <目录> -o <out.nr>` | 目录重新打包 |
| `unlock <in.nr> [-o out.nr] [--method uci\|rc] [--no-at]` | 一键解锁 |
| `menu` | 中文文本交互菜单 |
| 无参数 | 启动图形界面 |

`unlock` 关键参数：

- `--method uci`（默认）：写 uci-defaults；加 `--no-at` 表示不处理 AT 页；
- `--method rc`：写 rc.local 的一次性自删除脚本（仅 SSH+ADB）；
- `-o` 可空，默认 `<原名>-unlock.nr`。

示例：

```
python nr_tool.py verify backup.nr
python nr_tool.py unlock backup.nr --method rc -o backup-rc.nr
```

## 九、注意事项

1. **刷机/恢复有变砖与配置丢失风险**，操作前保留一份设备原始备份，确认可重新导入后再尝试，风险自负。
2. 开启 SSH/ADB 等于放开调试入口，**仅限可信网络环境使用**；用完建议及时关闭规则或修改 root 密码，不要直接暴露到公网。
3. 注入内容设计为**一次性**：方式一脚本由系统删除，方式二注入块由 `sed` 自删；重复对同一备份解锁也是幂等的（rc.local 中旧块会先被清除，永远只有一个块）。
4. 方式二会修改 `etc/rc.local`，但**保留其原有命令**，注入块始终位于最后一个 `exit 0` 之前；备份中没有该文件时会自动生成标准模板。
5. 打包只收集普通文件和符号链接，不单独打包空目录；空目录无需存在于 tar 中，不影响配置恢复。
6. 解包目标目录非空会被拒绝，属正常保护；请换空目录。
7. 工具不会删除你的任何备份或文件夹；输出文件写入采用"先写 .tmp 再替换"，不会产生半个损坏文件。

## 十、常见问题

**Q：双击 exe 没反应或很久才出窗口？**
A：单文件版首次运行要自解压，等十几秒；仍无反应多为杀软拦截，将 exe 加信任/白名单后重试。

**Q：方式一和方式二该选哪个？**
A：一般选**方式一（默认）**，它还能顺带显示 AT 页。只有当实测方式一生效不稳定（个别固件 uci-defaults 行为差异）时，再换方式二；方式二在开机更晚阶段主动 commit 并立即拉起 firewall/adbd。

**Q：恢复后 SSH 连不上？**
A：① 确认电脑接 LAN 口、与设备同网段、22 端口未被电脑防火墙/上游网络拦截；② 确认设备恢复后已正常重启过一次（注入仅在首次开机执行）；③ 账号 root / admin；④ 可换另一种注入方式再试。

**Q：网页恢复时提示备份无效/校验失败？**
A：说明 CRC 不符。请确认 `-unlock.nr`/`-repacked.nr` 是本工具生成（上传过程选 ASCII 模式可能损坏，应按二进制/原文件上传）；可用页签② verify 自查，PASS 才能被设备接受。

**Q：verify 报 crc 不匹配？**
A：文件被改动过但未用本工具重打包，或文件已损坏。请重新从设备导出原始 `.nr`，再走页签①。

**Q：我手工改了配置，怎么打包？**
A：页签③解包 → 改文件 → 页签④打包 → 页签② verify → 网页恢复。不要手工替换 gzip 内文件后直接上传（CRC 必错）。

**Q：图形 exe 能在命令行里跑 verify 看输出吗？**
A：不能。图形版 exe 不附加控制台（能执行、退出码正确，但不显示文字）。需要文本输出请用随附的 `.cmd` 或 `python nr_tool.py …`。

**Q：AT 指令页选项为什么有时是灰的？**
A：AT 页取消隐藏只在方式一（uci-defaults）下支持；选中方式二 rc.local 时该勾选框自动禁用，属设计如此。
